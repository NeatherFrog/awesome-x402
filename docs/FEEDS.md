# Внешние котировки для исследования

Необязательный адаптер `propdesk.feeds` получает исторические OHLCV через **публичный неофициальный Yahoo Chart endpoint**. Это удобный импорт исследовательских цен, не брокерское подключение и не гарантия доступности данных.

Локальный CSV остаётся воспроизводимым вариантом. После внешней загрузки сохраните сами бары, provenance и параметры исследования: повторный запрос того же диапазона может вернуть исправленную историю.

## Использование

Программный интерфейс:

```python
from propdesk.feeds import get_history

dataset = get_history("EURUSD", interval="1h", range_="3mo")
bars = dataset["bars"]
provenance = dataset["provenance"]
```

В веб-приложении используется общий маршрут `POST /api/research`:

```json
{"source":"yahoo","symbol":"EURUSD","interval":"1h","range":"3mo"}
```

Он загружает историю, выполняет исследование и возвращает полный отчёт. В нём `data.input_source="yahoo"`, `data.provenance` содержит сведения Yahoo, а `data.source="csv"` и `config.source="csv"` обозначают нормализованную реальную историю в общем движке. Это не означает независимую проверку источника.

Счёт, ордер и брокерская авторизация не создаются. При ошибке загрузки программа сообщает её, не подставляя синтетические цены под видом Yahoo.

Поддерживаемые интервалы: `15m`, `1h`, `1d`. Диапазоны: `1d`, `5d`, `1mo`, `3mo`, `6mo`, `1y`, `2y`, `5y`, `10y`, `max`. Для `15m` разрешены только `1d/5d/1mo`, для `1h` — не длиннее `2y`, для `1d` — все перечисленные.

Слишком короткий диапазон может не дать минимальные 300 баров для исследования. Ограничения провайдера могут быть строже и меняться. Сервер валидирует значения; произвольный endpoint или URL ввести нельзя.

Ticker ограничен 32 символами из `A–Z`, `a–z`, цифр, `^=._-`. Нужен реальный Yahoo ticker, а не произвольное название инструмента брокера.

## Что означают короткие названия

| Название в приложении | Yahoo ticker | Существенное отличие |
| --- | --- | --- |
| `EURUSD` | `EURUSD=X` | Индикативный FX feed, не bid/ask вашего брокера |
| `XAUUSD` | `GC=F` | **Фьючерсный proxy золота**, не spot XAUUSD |
| `NAS100` | `^NDX` | **Неторгуемый индекс**, не NAS100 CFD |
| `BTCUSD` | `BTC-USD` | Источник Yahoo для BTC/USD, не исполнение на выбранной криптобирже |

Особенно важно проверить proxy: прибыль на золотовом futures-графике нельзя переносить в spot CFD, а индексная цена сама по себе не позволяет исполнить NAS100-сделку. Funding, rollover, basis, spread, multiplier и торговые часы различаются.

Для собственного ticker проверьте площадку, валюту, adjustment и спецификацию. Адаптер не переводит автоматически стоимость пункта в валюту проп-счёта и не определяет допустимый contract size.

## Закрытые бары и пропуски

Каждый `time` — **UTC open-label бара**. Возвращаются только бары, которые адаптер считает закрытыми:

- `15m`/`1h`: open timestamp + длительность не позже времени запроса.
- `1d`: текущая UTC-дата исключается, дополнительно требуется open + 24 часа не позже времени запроса.

Daily-фильтр намеренно консервативен. Реальные session-close и биржевой календарь неизвестны; он может исключить уже завершённый бар. Результат не подтверждает, что последнее значение доступно для live execution.

Строки с отсутствующими/`null` OHLC пропускаются с указанием числа `skipped_rows`. При отсутствующем объёме используется `0` и предупреждение. Не воспринимайте это как реальный нулевой объём; проверьте пробелы до бэктеста. Адаптер не заполняет отсутствующие цены будущими значениями.

После фильтрации применяется канонический валидатор [DATA.md](DATA.md): положительные конечные цены, корректная оболочка high/low, UTC и строго возрастающее время. Структурная валидация не доказывает качество источника.

## Происхождение и ограничения

`provenance` сохраняет provider, время получения, URL источника, interval/range, число пропущенных строк и предупреждения. `last_closed_bar_open` — open-label последнего возвращённого бара; `last_closed_at` — его номинальный close по длительности интервала, а не проверенное закрытие сессии. Provider обозначен как `Yahoo Chart (public unofficial endpoint)`; это не биржевой SLA и не проверенная лицензия для коммерческого использования.

Research работает с нормализованными импортированными барами; отметка внешнего источника и provenance должны сохраняться отдельно. Техническое происхождение `csv` внутри движка не означает, что пользователь вручную проверил Yahoo feed.

Адаптер не предоставляет:

- Broker bid/ask, ликвидность, order book и подтверждённые execution prices.
- Календарь биржи, новости и точную доступность проп-сессии.
- Funding, borrow, swap, transaction fees и правила rollover.
- Автоматическое подтверждение актуальных правил фирмы.
- Sentiment, статистическое доказательство edge и portfolio simulation.

Обновление исторического набора не означает торговую рекомендацию. Последний сетап требует проверки данных, расходов, счёта и правил по [PLAYBOOK.md](PLAYBOOK.md).

## Сеть и проверка

Доступ выполняется стандартной библиотекой Python по HTTPS к фиксированному `query1.finance.yahoo.com`. Redirect допускается только по HTTPS на тот же host или `query2.finance.yahoo.com`. TLS-проверка сохраняется; auth/секреты для этого публичного endpoint не нужны. Timeout — 15 секунд, ответ — не более 8 MiB, набор — не более 30000 баров.

В текущей облачной среде проверка Yahoo упирается в proxy `403 Forbidden`. Успешная загрузка реальных Yahoo-цен в этой среде **не подтверждена**; тесты на fixtures проверяют разбор и фильтрацию, не сетевую доступность и полноту истории.

Для сетевого использования нужны разрешённые `query1.finance.yahoo.com` и `query2.finance.yahoo.com`. После изменения сети повторите реальный запрос и проверьте provenance/бары; сохранённая настройка сама по себе не доказывает работу.

Если провайдер возвращает ошибку, rate limit или пустой набор, используйте проверенный CSV и сохраните причину отказа. Не отключайте TLS и не превращайте ошибку в демо с подписью «реальные данные».
