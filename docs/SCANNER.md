# Автоматический выбор рынка и исследовательской модели фирмы

Сканер принимает подготовленные OHLCV-истории, сравнивает рынки на обучении и автоматически выбирает **одного первичного кандидата**. Он проверяет этот выбор на отдельном финальном периоде. Если выбор не проходит фильтры, результат — «подходящего кандидата нет». Более красивый результат другого holdout не становится заменой.

Модуль [propdesk/scanner.py](../propdesk/scanner.py) не загружает котировки, не пишет файлы, не подключается к брокеру и не отправляет ордера. Получение истории, сохранение снимков и выполнение фоновых задач принадлежат вызывающему сервису. `planning_only: true`, `live_orders: false` и `live_orders_enabled: false` установлены в каждом отчёте.

## Что сравнивается

- От 1 до 12 наборов данных; 300–30 000 полностью закрытых баров в каждом. UTC-время, порядок, уникальность, конечные числа и OHLC-envelope проверяются стандартным валидатором.
- На каждом рынке проверяются семь фиксированных семейств и по два существующих набора параметров. Первые 60% баров используются для выбора; train fraction может быть заранее задан в допустимом диапазоне движка. Walk-forward целиком находится внутри этой обучающей части.
- Лучшее семейство каждого рынка выбирается только по фиксированному train score движка. Рынки ранжируются по этому же score; при равенстве выигрывает тикер по алфавиту. Изменение только последующих цен не меняет рейтинг или параметры.
- До любого полного бектеста создаётся `training_lock` с хешем, первичным рынком, максимум тремя диагностическими кандидатами, обучающими метриками, параметрами, стоимостью исполнения и хешами обучающих данных. `on_lock` получает независимую копию, чтобы сервис мог сохранить её **до первого holdout**.
- Финальные результаты вычисляются только для этих максимум трёх рынков. Полный движок сохраняет диагностические результаты семейств, однако автоматический выбор остаётся ограничен заранее объявленным победителем каждого рынка и глобальным первичным рынком.

К обычным фильтрам движка добавлен описательный **99% moving-block bootstrap интервал mean R** с 3000 повторами. Обязательны минимум 20 holdout-сделок и положительная нижняя граница. Это более строгий диагностический фильтр для максимум трёх рынков, а не доказанный предел ложных открытий: зависимость активов, повторные сканы одного периода и смена режима остаются источниками ошибки.

`primary_symbol` обозначает обучающего победителя независимо от успеха. `selected_symbol` появляется только если **этот же рынок** прошёл проверку. При его отказе все вложенные `selected_strategy` очищаются, включая прибыльные диагностические рынки. Результаты сравнения сохраняются для объяснения; новая автоматическая стратегия из них не выбирается.

## Издержки, размер контракта и валюта

По умолчанию модуль использует риск 0,25%, комиссию 2 bp на сторону, проскальзывание 1 bp на сторону, полный spread 1 bp и плечо максимум 2×. Размер счёта, шаг позиции и бюджет просадки берутся из выбранного профиля. Сервис может заранее передать другой консервативный набор настроек; все значения проходят числовую проверку движка.

Для разных классов активов вызывающий сервис может передать `execution_model` на каждый набор данных. Разрешены только `fee_bps`, `fee_per_unit`, `spread_bps`, `slippage_bps`, `contract_multiplier`, `quantity_step` и `max_leverage`. Эти значения применяются одинаково до обучения и до финальной проверки и записываются в lock. Например, фиксированная комиссия на целый micro-futures контракт отличается от процента на FX-оборот. Нулевая комиссия в bp при ненулевом `fee_per_unit` не означает бесплатную торговлю. Это **предположения**, пока их не подтвердили спецификация брокера и фактическое исполнение. Сам сканер не угадывает контрактный multiplier, margin или стоимость rollover.

Quote currency должна соответствовать валюте счёта. Для USD-счёта USDJPY с ценой в JPY исключается с `needs_currency_conversion`: историческая динамическая конверсия не реализована. Yahoo `GBp` означает pence и сохраняется как отличающаяся единица `GBX`, а не превращается в GBP. При отсутствующей валюте для инструмента, который нельзя однозначно распознать как FX-пару, используется явно отмеченное предположение о валюте счёта; его нужно проверить по брокерской спецификации.

Статус источника также влияет на допуск. Явные demo/synthetic/generated/illustrative метки всегда блокируют выбор. Yahoo и явно объявленный CSV передают настоящую исходную provenance в вложенный отчёт; `data.source: csv` означает каноническую импортированную OHLCV-историю в существующем API движка, а не обязательно исходный формат CSV. Неустановленный источник получает `unknown` и не квалифицируется. Пользовательская provenance не является независимой экспертизой поставщика данных.

## Выбор профиля фирмы

Сравнение использует только сделки **первичного прошедшего рынка** и требует минимум 30 out-of-sample сделок. Generic-профили не дают рекомендации даже при красивых модельных результатах.

Профиль должен иметь `status: user_verified`, публичный HTTPS-источник и дату проверки не старше 90 дней, без будущей даты. Допустимы строгая дата `YYYY-MM-DD` как пользовательское подтверждение на начало UTC-дня и полный UTC timestamp. Это поле подтверждения правил; формат цены или времени рыночного бара остаётся строгим UTC timestamp. Наивный datetime без timezone не принимается как время проверки. Запрет автоматической торговли и несовпадение валюты счёта исключают профиль из автоматической рекомендации.

Модель [payout.py](../propdesk/payout.py) использует завершённые сделки на рабочий день **полного holdout**, включая простои до первой и после последней сделки. Сканер не подменяет редкую дневную стратегию предположением «три сделки в день». Пятидневная модель для crypto всё равно остаётся приближением.

Лучшим считается профиль с наибольшим **положительным поддержанным моделью net expected value** первой выплаты за попытку, после fee. При равенстве используется ID по алфавиту. Отрицательный EV, недостаточная выборка, неподтверждённые правила или отказ первичного рынка дают `selected_profile_id: null` с причинами. Выбор называется исследовательским кандидатом: он не устанавливает будущую доходность, принятие стратегии фирмой или одобрение payout-заявки. Подписки, дополнительные challenge-фазы, ограничения новостей и реальная продолжительность удержания моделью полностью не воспроизводятся. R-доходности масштабируются на размер каждого счёта; округление lot на другом размере счёта отдельно не проверяется.

## API модуля

```python
from propdesk.scanner import scan

report = scan(
    {
        "EURUSD": {
            "bars": canonical_closed_bars,
            "provenance": {
                "provider": "Yahoo Chart (public unofficial endpoint)",
                "quote_currency": "USD",
            },
            "execution_model": {
                "fee_bps": 0.3, "spread_bps": 1, "slippage_bps": 0.5,
                "contract_multiplier": 1, "quantity_step": 1000,
            },
        },
    },
    settings={"prop_profile": confirmed_or_illustrative_profile},
    profiles=available_user_profiles,
    on_lock=persist_training_lock,
    progress=record_progress,
)
```

Оба callback принимают **один словарь**, а не пару аргументов. Фазы progress: `training`, `training_locked`, `holdout`. Ошибка сохранения lock прерывает работу до holdout. Callback не получает изменяемую ссылку на внутренний lock. Без callback lock существует в памяти и сохраняется в финальном отчёте; сервис отвечает за durable snapshot.

Финальный отчёт содержит `training_lock`, `training_lock_sha256`, `primary_symbol`, `selected_symbol`, `selected_strategy`, `selected_profile_id`, `firm_comparison`, `exclusions` и `markets`. Каждый элемент `markets` включает стандартный вложенный `report`, диагностический rank, строгий confidence и причины отказа. `market_context` хранит валюту, единицы и execution assumptions; вызывающий сервис может дополнить его актуальным снимком котировки. Старый архив сам по себе не становится текущим сетапом.

## Проверки

```bash
python -m unittest discover -s tests -p 'test_scanner.py' -v
```

Двенадцать тестов покрывают границы входа, обучающие prefix-only вызовы, lock до holdout, неизменность выбора при замене последующих цен, запрет замены проигравшего primary, demo denial, валютные единицы, издержки и точный единый execution model, неподтверждённые/устаревшие правила, date-only attestation, полный календарный знаменатель cadence и отказ от отрицательного либо неподдержанного EV.
