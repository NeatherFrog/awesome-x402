# Часовые пояса на Windows

Для базового запуска достаточно Python 3.11+: дополнительные Python-пакеты не нужны. Модуль `zoneinfo` входит в Python, но стандартная установка Windows обычно не содержит базу IANA. Поэтому приложение использует системную базу, если она доступна, и встроенные TZif для `Europe/Prague`, `Europe/Kyiv`, `America/New_York` и `America/Chicago`, если нужная зона отсутствует. Старое имя `Europe/Kiev` поддерживается как alias Kyiv. UTC и его стандартные алиасы используют `datetime.timezone.utc` при отсутствии системных данных.

Встроенные зоны сохраняют исторические переходы, летнее время и повторяющийся час осенью: фиксированное смещение вроде UTC−5 не заменяет `America/New_York`. Данные взяты из установленного Debian `tzdata 2026b-0+deb13u1`, выпуск IANA `2026b`, и распространяются как public domain. Происхождение и SHA-256 каждого файла указаны в `propdesk/tzdata/README.md`; обновления этих файлов приходят вместе с обновлениями приложения.

Другие IANA-зоны, например `Asia/Tokyo`, доступны, когда их предоставляет система. Если такой базы и встроенного файла нет, приложение сообщает, что зона неизвестна. Оно не подменяет её UTC: это изменило бы границы дневного лимита. Для нестандартной зоны на Windows можно добавить официальную базу IANA или официальный пакет `tzdata`, если он нужен вашему профилю; это дополнительная настройка, а не требование базового запуска.

Указанный в профиле часовой пояс должен соответствовать договору фирмы и времени reset. Наличие корректной зоны не подтверждает сами правила фирмы. Новые законодательные изменения требуют актуального выпуска базы, а точный equity на reset по дневным свечам восстановить нельзя.
