# Условные сетапы PROP LAB

Планировщик отвечает на вопросы: какой сигнал действительно появился на последнем закрытом баре, где находится исходный стоп и цель, когда идея перестаёт действовать и какие сведения ещё нужно проверить. Он строит план для бумажной проверки. Ни один его результат не разрешает реальный ордер: `planning_only=true`, `can_trade=false`.

Числовой план появляется только для замороженного победителя обучения, который прошёл критерии допуска на отложенных данных. Планировщик не заменяет провалившегося кандидата стратегией с лучшим результатом теста. Синтетическая история, неподтверждённое происхождение данных, провал проверки правил, устаревший снимок и несовпадение сигнала с последним баром блокируют план. Допуск по прошлой истории не доказывает будущую прибыль.

## Три состояния

| Состояние | Что делать |
| --- | --- |
| `wait` | Последний закрытый бар не дал нового сигнала. Прочитать условие выбранного семейства и ждать следующий закрытый бар. Числовые уровни отсутствуют. |
| `blocked` | Устранить причину в `reasons`: например, загрузить свежие реальные данные или подтвердить новостной календарь. Числовые уровни отсутствуют. |
| `paper_review` | Изучить условный план, проверить текущие условия фирмы, фактическую цену входа, спред и риск отдельным чекером. Использовать только бумажную проверку. |

Показанный вход — зона ±0.1 текущего ATR14 вокруг цены сигнального закрытия. Исходный бэктест входит по open следующего бара; он **не тестировал исполнение внутри этой зоны**. Зона служит визуальным допуском для обзора и не меняет модель заполнения ордера в исследовании.

Стоп и центральная цель дословно сохраняются из `latest_signal.stop` и `latest_signal.target`. Зона цели равна ±0.1 ATR вокруг исходной цели. Зона отмены равна ±0.05 ATR вокруг стопа. **Пересечение самого стопа отменяет идею**: ширина зоны отмены не разрешает отодвигать стоп. `rr` вычисляется от сигнального закрытия; при другом входе фактическое отношение прибыли к риску нужно пересчитать в чекере.

## Время и срок действия

В импортируемом CSV поле `time` обозначает **открытие** бара. `reference_time` сохраняет эту метку; `reference_close_time` равен открытию плюс таймфрейм. Сигнал недоступен, пока не наступило закрытие.

Максимальный возраст снимка — большее из трёх таймфреймов и 15 минут. Дополнительно план истекает при ожидаемом закрытии следующего бара (`expires_at`): к этому времени нужен новый снимок. Это консервативное правило обновления плана, не модель торговой сессии.

Календарь биржи, праздники, перерывы сессии, момент фактического получения котировки и точность таймфрейма не определяются автоматически. Для дневных баров open+1440 минут может отличаться от реального закрытия биржевой сессии. Для нерегулярной истории предполагается типичный интервал и показывается предупреждение. Приложение не переносит срок действия через выходные и праздники по догадке.

## Контекст рынка

Контекст вводится пользователем. Автоматического макропотока, сканера настроений и новостного фида в этом модуле нет. Источники показываются в `context.sources`.

- `macro_cycle`: `unknown`, `expansion`, `slowdown`, `recession`, `recovery`. `macro_source` — необязательная строка. Это качественная гипотеза пользователя, которая не подбирает другую стратегию.
- `sentiment`: оценка от -1 до 1, источник, время наблюдения UTC и флаг ручного подтверждения. Будущие, неподтверждённые и старше 24 часов наблюдения не получают текущую числовую оценку. Несогласие подтверждённых настроений с направлением создаёт предупреждение, но не превращается в подогнанный фильтр доходности.
- `news`: ручное подтверждение календаря, источник, время его проверки UTC (`observed_at`) и максимум 200 событий. Текущим считается подтверждённый календарь с источником и проверкой не старше 6 часов, без будущей даты.

Для каждого события нужны `time`, `known_at`, `impact` (`high`, `medium`, `low`), `title` и `currency`. Событие с `known_at` позже времени решения исключается: исторический план не получает будущих знаний. Из списка невозможно доказать полноту календаря; ручное подтверждение означает заявление пользователя, а не независимую проверку.

Важное событие блокирует новый вход в окне 30 минут до и 15 минут после события. Все важные события из подтверждённого списка трактуются консервативно, без автоматического сопоставления валют с активом. Это **политика планировщика**, а не проверенная на истории торговая стратегия. Реальные окна фирмы могут отличаться. Если профиль запрещает новостную торговлю, неизвестный календарь также блокирует план.

Макроцикл, настроения и новостной фильтр не использовались при обучении или подтверждении edge. Чтобы оценить их финансовый эффект, нужна отдельная историческая выборка контекста с исходными временами доступности (`known_at`), заранее зафиксированные правила и новый отложенный тест. Текущие ручные сведения нельзя задним числом распространить на исторический бэктест.

## Пример контекста

```json
{
  "macro_cycle": "slowdown",
  "macro_source": "Ручной обзор опубликованных показателей",
  "sentiment": {
    "score": -0.4,
    "observed_at": "2026-10-01T11:30:00Z",
    "source": "Ручной обзор",
    "confirmed": true
  },
  "news": {
    "confirmed": true,
    "source": "Календарь, проверенный пользователем",
    "observed_at": "2026-10-01T12:00:00Z",
    "events": [
      {
        "time": "2026-10-01T14:00:00Z",
        "known_at": "2026-09-30T10:00:00Z",
        "impact": "high",
        "title": "Пример запланированной публикации",
        "currency": "USD"
      }
    ]
  }
}
```

Все даты принимаются только в явном UTC с `Z` или `+00:00`. Пример не описывает реальное экономическое событие.

## Контракт модуля

```python
from propdesk.setups import build_setup
plan = build_setup(research, context=None, now=None)
```

`research` — сохранённый результат исследования, дополненный причинным `market_context` (`last_bar`, `atr14`, `timeframe_minutes`) и `profile_rules`. Для старых исследований без снимка потребуется новое исследование. `now` по умолчанию — текущее UTC; переданная дата должна иметь часовой пояс. Для исторического аудита используют время решения и лишь сведения, уже известные к нему.

Результат содержит состояние, актив, семейство стратегии, направление, зоны входа/цели/отмены, исходный стоп, RR, условия отмены, нормализованный контекст, причины и предупреждения, временные метки и обязательные признаки бумажного режима.
