# Архитектура и API

`propdesk/market.py` проверяет и создаёт данные; `feeds.py` импортирует историю Yahoo; `strategies.py` содержит причинные индикаторы; `backtest.py` делает train, walk-forward и holdout; `risk.py` проверяет план сделки; `compliance.py` проверяет непрерывный holdout по loss floors; `payout.py` моделирует первую выплату. `setups.py` строит условный план; `news.py` хранит датированный внешний календарь. `scanner.py` выбирает рынок и исследовательский профиль фирмы; `jobs.py` выполняет фоновую задачу, `autopilot.py` планирует её раз в UTC-день. `store.py` хранит пользовательское состояние в SQLite; `server.py` связывает расчёты с девятью разделами `static/`. `updater.py` и `launch.py` отвечают за совместимые обновления и перезапуск.

Все операции относятся к исследованию или бумажному планированию. Торгового адаптера нет. Сигнал webhook не вызывает ордер; запись дневника не доказывает реальное исполнение.

## Исследование

```json
{
  "source": "demo",
  "symbol": "EURUSD",
  "profile_id": "generic-static",
  "config": {
    "risk_pct": 0.25,
    "account_size": 100000,
    "fee_bps": 0.2,
    "spread_bps": 1,
    "slippage_bps": 0.5,
    "contract_multiplier": 1,
    "max_leverage": 5,
    "train_fraction": 0.6
  }
}
```

Для `source:csv` добавьте `csv_text`. Дополнительный `strategy_ids` ограничивает каталог. Риск измеряется в процентах, вероятности модели выплат — долями от 0 до 1. Неподдержанные метрики, например profit factor без убытков, могут быть `null`; API не выдаёт `NaN` или `Infinity`.

Для Yahoo передайте `{"source":"yahoo","symbol":"EURUSD","interval":"1h","range":"3mo"}`. Отчёт сохраняет `data.input_source:"yahoo"` и `data.provenance`; основной движок принимает нормализованную реальную историю как `data.source:"csv"`/`config.source:"csv"`. При ошибке сети демо не подставляется. Бары имеют UTC open-label и должны уже быть закрыты; внешние quotes не являются брокерскими fills.

## Фоновый автопоиск

Пример `POST /api/scanner/jobs`:

```json
{
  "source": "yahoo",
  "interval": "1h",
  "range": "3mo",
  "config": {"risk_pct": 0.25, "use_market_costs": true}
}
```

`symbols` необязателен; допускается от 1 до 12 тикеров. `source:"reference"` использует встроенные архивы; общий временной диапазон проверяется, несовместимые валюты/периоды исключаются. Default Yahoo-кандидаты: EURUSD, XAUUSD, NAS100, BTCUSD, MES=F, MNQ=F, AAPL, MSFT. Proxy-инструменты раскрываются в provenance.

После HTTP 202 опрашивайте задачу по id. Сервис сохраняет training lock **до holdout**. Глобальный primary выбирается только на train, до трёх рынков проверяются диагностически; провал primary не заменяется победителем другого holdout. Дополнительный 99% описательный bootstrap и минимум 20 сделок ограничивают paper-review, но не доказывают будущий edge.

В `execution_assumptions` видны per-market расходы/размеры: fee/slippage bps за сторону, полный spread, денежная fee per unit, multiplier и quantity step. Это исследовательские предположения. При `use_market_costs:false` используется единая явно заданная модель. Выбор фирмы требует не менее 30 OOS-сделок, свежего пользовательского подтверждения правил и положительного поддержанного EV; `selected_profile_id` может оставаться `null`.

`POST /api/scanner/use` сохраняет выбранный снимок для обзора и сетапов; он не создаёт ордер. Старый архив остаётся старым после переноса. Подробные контракты: [SCANNER.md](SCANNER.md), [FIRM_SELECTION.md](FIRM_SELECTION.md), [SETUPS.md](SETUPS.md).

## Ежедневный режим

`GET /api/autopilot` возвращает состояние напрямую. `POST /api/autopilot {"enabled":false}` выключает будущие автоматические попытки; `{"enabled":true}` включает. `{"action":"run"}` — отдельный явный запуск и HTTP 202. Допустимые настройки включают `settings` с `source:"yahoo"`, тикерами, interval/range, profile_id и ограниченной конфигурацией риска/издержек; токены в них не принимаются. Настройки нельзя менять во время активной задачи.

На первом запуске установленного пакета под лаунчером режим включён, в development checkout выключен. `TRADING_AUTOPILOT_DEFAULT=0/1` задаёт исходный default; существующий `autopilot.json` имеет приоритет. Default universe — восемь Yahoo-рынков, 1h/2y, risk 0,25% и per-market costs. Планировщик работает только при запущенном сервере. Он резервирует не более одной автоматической попытки в UTC-день до enqueue, ждёт research/updater locks и сохраняет состояние атомарно под межпроцессной блокировкой. При неизвестной активной задаче новая не создаётся; синтетической подстановки нет.

По завершении сохраняется primary report, в том числе отказ. Положительный диагностический holdout не заменяет primary. `selected_symbol:null` и отсутствие подтверждённой фирмы оставляют бумажный сетап заблокированным. Выключение режима не означает отмену уже начатого исследования. Поток планировщика останавливается и присоединяется при завершении сервера.

## Экономический календарь

Перед Yahoo scan сервис вызывает `CalendarFeed.refresh()`; тот же refresh доступен через `POST /api/news/refresh {}`. `GET /api/news/status` читает состояние и сам не обращается к сети. Фиксированный источник — `https://nfs.faireconomy.media/ff_calendar_thisweek.json`, Forex Factory weekly calendar via Fair Economy Media. Refresh TTL — час; failed attempts также ограничиваются в рамках текущего процесса. Подтверждение требует непустого корректного календаря текущей однозначной provider Sunday–Saturday week и возраста максимум 6 часов.

`observed_at`/known_at — фактический UTC получения, а не выдуманное время публикации события. Forecast/actual/previous не становятся исследовательскими признаками. Holiday/Non-Economic не считаются экономическим blackout; полнота schedule не доказана. Неверная, пустая, устаревшая или недоступная лента остаётся `confirmed:false`, события не подставляются. На финальной проверке 1 октября 2026 получен HTTP 200, 142 строки текущей недели и совпадающий SHA-256 независимого ответа/реального кэша. Во время serving отдельный поток обновляет календарь раз в час, пока автопилот включён; GET не запускает transport. News context не является разрешением ордера и не доказывает прибыльность фильтра. Контракт и пределы: [NEWS.md](NEWS.md).

## Обзор реальных правил

`GET /api/firms/review` читает `docs/prop-firm-review.json`: `sources` с exact URL/time/body hash, парафразы `facts`, документальные `products`/`draft_products` и `decision`. Все drafts имеют `user_verified:false`. Условный `candidate_product_id` отражает пригодность договорных условий для дальнейшего исследования; `selected_profile_id`, `market`, `expected_profit` остаются `null`, `can_buy:false`. Payload не создаёт профиль и не подтверждает договор за пользователя. Особые формулы 1-Step Best Day, XFA и полные фазовые переходы не сводятся к общему generic-профилю. Подробности: [PROP_FIRM_REVIEW.md](PROP_FIRM_REVIEW.md).

`POST /api/payout` принимает `strategy_id`, `profile_id`, `config` с `paths`, `risk_pct` и временным горизонтом. Если стратегия не прошла фильтр или данные синтетические, нужна явная опция `allow_illustrative:true`; результат будет учебным. Bootstrap-пути — пересэмплирование одной выборки, а не независимые реальные испытания стратегии.

## Безопасность и эксплуатация

По умолчанию сервер слушает loopback. Это локальный инструмент для одного пользователя, без многопользовательской аутентификации. Не выставляйте весь API в Интернет: при внешнем доступе обязательны HTTPS, аутентификация, авторизация и ограничение частоты запросов на reverse proxy. Для TradingView публикуйте только маршрут webhook с токеном, не дневник и редактор правил.

API изменений принимает JSON и проверяет Origin для браузерных запросов; CORS не включён. Host по умолчанию ограничен локальными именами и адресом сервера. Для защищённого reverse proxy укажите его hostname без порта в `TRADING_ALLOWED_HOSTS`. HTML не содержит внешних CDN или аналитики, CSP ограничивает скрипты своим сервером. SQLite использует параметризованные запросы. Лимит тела — 5 МБ, исследование одновременно одно, размеры расчётов ограничены. Токен webhook сравнивается constant-time и не сохраняется в базе. Это не заменяет отдельный аудит перед внешним развёртыванием.

Локальные процессы не переживают публикацию cloud snapshot. Повторный запуск: перейти в существующий `/workspace/trading`, проверить Python 3.11+, запустить `python3 -m propdesk serve`. Рабочий каталог уже изолирован: новый Git worktree не нужен.

Windows portable ZIP использует официальный изолированный CPython 3.13.16 из `runtime/`. Лаунчер предпочитает его; source ZIP/macOS/Linux требуют установленный Python 3.11+. Updater сохраняет runtime и пользовательское состояние. Сам Python обновляется заменой полного portable-пакета; native Windows CI отдельно проверяет сборку, запуск и update-сценарий. Версия приложения — 0.3.1.
