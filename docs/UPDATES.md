# Установка и обновления

## Первый запуск

1. Для **Windows x64 portable ZIP** отдельный Python не нужен: пакет включает официальный **CPython 3.13.16**. Для macOS/Linux и обычного source ZIP установите Python **3.11+** с python.org, если он ещё не установлен.
2. Распакуйте ZIP PROP-LAB целиком в обычную доступную для записи папку. Не запускайте программу прямо внутри ZIP и не устанавливайте её в защищённую системную папку.
3. Windows: двойной щелчок по `START-WINDOWS.bat`. macOS: `START-MAC.command`. Linux: `bash START-LINUX.sh`. Браузер откроется после готовности сервера.
4. Оставьте окно запуска работающим. Для завершения нажмите Ctrl+C в нём. Не закрывайте это окно во время установки обновления.

Дополнительные пакеты, Git, Node.js и ключи брокера для базового запуска не нужны. Программа использует локальный браузер, а расчёты и база работают на вашем компьютере.

`START-WINDOWS.bat` предпочитает `runtime/python.exe`; при отсутствии встроенного runtime проверяет установленный Python. Встроенный интерпретатор изолирован от системных Python-пакетов. Сборка получает фиксированный официальный архив по HTTPS, сверяет его с SHA-256, закреплённым в исходном коде, и проверяет подписи native-файлов на Windows. Фактический запуск готового portable-пакета и обновления проверяет отдельный Windows CI; его результат должен быть опубликован вместе с пакетом. Облачные Linux-тесты не заменяют эту проверку.

На macOS политика запуска скачанных файлов может требовать открытия через контекстное меню Finder. Универсальная команда из папки программы: `python3 launch.py`. Если порт 8000 занят другой программой, лаунчер выбирает другой свободный порт и не останавливает чужой процесс.

## Версия 0.3.3

Native-тесты версии 0.3.2 прошли полностью на Windows: 369 проверок. Последующая проверка подписи runtime выявила несовместимость получения JSON через stdin PowerShell; исправлена перед публикацией portable-пакета. Проверка остановки сервера требует реального отказа нового TCP-соединения.

Соединения SQLite закрываются сразу после завершения транзакции, включая ошибки. Windows-проверки обновления используют настоящий ZIP с недопустимыми байтами пути и единый canonical root для инъекции сбоя записи; тесты защиты и восстановления не отключены.

Сборка сохраняет исходные байты архивов данных при Windows checkout и запускает тесты с явным UTF-8. Проверка ресурса версии Python учитывает кодирование Windows FileBuildPart; SHA-256 официального runtime закреплён без пользовательского override. Ошибки native-этапов публикуются в отдельные GitHub Checks для диагностики.

В установленном пакете под лаунчером по умолчанию включено ежедневное исследование восьми Yahoo-рынков, **1h/2y**, пока программа работает. Максимум одна автоматическая попытка в UTC-день; ручное обновление доступно отдельно. В development checkout режим по умолчанию выключен. `TRADING_AUTOPILOT_DEFAULT=0/1` задаёт только первый default; уже сохранённое значение имеет приоритет. Настройки и отметки попыток хранятся рядом с пользовательской базой в `autopilot.json`.

Занятое исследование или установка обновления откладывают запуск. Сетевой отказ не подменяется демо. Основной отчёт сохраняется и при отказе всех кандидатов; ордеров нет. Выполненное 1 октября 2026 исследование получило 74 620 реальных баров и отклонило первичный MES-кандидат: [CURRENT_RESEARCH.md](CURRENT_RESEARCH.md). Публичные правила FTMO/Topstep просмотрены отдельно: [PROP_FIRM_REVIEW.md](PROP_FIRM_REVIEW.md).

Экономический календарь обновляется перед Yahoo-автопоиском и по отдельной кнопке. Подтверждение требует корректной текущей недели и возраста не более 6 часов. В проверке 1 октября 2026 endpoint календаря недоступен; состояние остаётся неизвестным. Кэш не делает старые или отсутствующие события подтверждёнными: [NEWS.md](NEWS.md).

## Обновления с GitHub

Источник кода: **NeatherFrog/awesome-x402**, ветка **main**. Старое имя GitHub-репозитория сохранено; сам продукт называется Trading / PROP LAB. Будущие изменения публикуются в этой ветке. Раздел «Обновления» показывает текущую версию и commit вашей установки.

Нажмите **«Проверить»**, затем **«Обновить из GitHub»**. Можно нажать кнопку установки непосредственно: она сама проверяет актуальный commit. Обновление скачивает ZIP конкретного GitHub commit по HTTPS, проверяет структуру и release-манифест, создаёт резервную копию исходников и заменяет только файлы программы. При успешной установке лаунчер автоматически перезапускает сервер, затем страница перезагружается.

Дневник, профили и исследования в `.local/propdesk.sqlite3`, локальные настройки/кэши, `.env`, виртуальное окружение и собственные файлы данных не заменяются. **Каталог `runtime/` также сохраняется:** обычная кнопка обновляет приложение, а не Python. Для обновления безопасности встроенного Python установите полный новый portable-пакет, предварительно сохранив пользовательский каталог `.local/` или свой `--data-dir`. Резервная копия кода и состояние обновлений лежат в `.local/updater/`; при `--data-dir` используется тот же каталог пользовательского состояния с вложенной папкой `updater`.

Если вы самостоятельно редактировали исходные файлы, программа остановит установку, а не затрёт изменения. Сохраните такие правки отдельно и восстановите исходную установленную копию перед повторной попыткой. При ошибке записи уже заменённые исходники автоматически восстанавливаются из резервной копии. Это не делает обновление атомарным при внезапном выключении компьютера: не прерывайте установку.

Если запускать сервер непосредственно через `python -m propdesk serve`, код можно обновить, но автоматического перезапуска нет. Используйте входящие в архив START-файлы или `launch.py` для полного сценария с одной кнопкой.

## Авторизация и доступ

Публичный репозиторий обновляется без токена; GitHub может ограничивать частоту запросов. Для закрытого репозитория либо личного лимита API можно задать `TRADING_GITHUB_TOKEN` в окружении запуска, с доступом на чтение содержимого этого репозитория. Уже доступный `GH_TOKEN` также используется. Не пишите значение в исходники, заметки, URL или Git и не отправляйте его в чат. Программа не сохраняет его в базе и не переносит на произвольные сервера.

Нужен HTTPS-доступ к `api.github.com` и `codeload.github.com`. В cloud-среде API может быть заблокирован прокси, хотя Git-доступ работает; это не доказывает отсутствие авторизации. В таком случае UI показывает ошибку доступа, а существующая программа и дневник продолжают работать.

## Готовый пакет и копия разработки

Готовый ZIP содержит `.installed.json`: commit и SHA-256 исходных файлов первоначальной установки. Он не содержит дневника, секретов или `.git`. Не удаляйте этот файл. Обычный Git checkout предназначен для разработки; применение обновления кнопкой в нём отключено, чтобы не затронуть незакоммиченные правки. Для разработчика используются обычные Git pull/commit/push.

Проверки SHA и HTTPS устанавливают целостность относительно полученного GitHub commit, а не подпись независимого автора. Обновляя программу, вы доверяете владельцам указанного репозитория и их коду.
