# Trading / PROP LAB

Программа для исследования торговых стратегий, проверки проп-правил и бумажного планирования. Русский интерфейс, Python **3.11+**, обычный браузер; сервер, расчёты и SQLite используют стандартную библиотеку без внешних runtime-пакетов.

Есть рабочий кабинет, реальные архивные исследования, проверка рисков, условные сетапы, дневник и экспорт TradingView. Брокерские ордера не отправляются. Положительный исторический результат не означает подтверждённый будущий edge или выплату.

## Установка и запуск

Распакуйте готовый ZIP целиком в доступную для записи папку. Нужен установленный Python 3.11 или новее; запуск из ZIP без распаковки не поддерживается.

- Windows: `START-WINDOWS.bat`.
- macOS: `START-MAC.command`.
- Linux: `bash START-LINUX.sh`.
- Универсальный запуск: `python3 launch.py` из папки программы.

Лаунчер запускает сервер и открывает браузер после проверки готовности. Оставьте окно запуска работающим; Ctrl+C завершает программу. При занятом порте он выбирает свободный, сохраняя чужой процесс. Git, Node.js и ключи брокера для обычного запуска не нужны.

Из checkout сервер также запускается напрямую:

```bash
python3 -m propdesk serve --host 127.0.0.1 --port 8000
```

Откройте адрес локального сервера на выбранном порту. Для фоновой разработки: `bash scripts/start.sh`; функциональная готовность: `python3 scripts/check_ready.py`. Можно использовать `make run`. Процессы облачной среды требуется запускать снова после восстановления.

Подробности установки, ZIP и обновлений: [UPDATES.md](docs/UPDATES.md). Отчёт выполненных проверок: [VALIDATION.md](docs/VALIDATION.md).

## Первый сеанс

1. Запустите демо в лаборатории для знакомства. Его синтетические результаты никогда не подтверждают edge.
2. Изучите встроенные архивные отчёты или загрузите собственные исторические OHLCV. Выберите инструмент, задайте издержки, multiplier, шаг quantity и плечо. Последняя свеча должна быть закрыта.
3. Создайте профиль по действующим условиям своего продукта/этапа. Зафиксируйте источник, дату и формулы; встроенные профили не описывают проверенную реальную фирму.
4. Проверьте train, отдельный holdout, walk-forward, количество сделок и причины отказа. Провалившийся train-кандидат не заменяется красивым результатом другого holdout.
5. В «Сетапы» проверьте свежесть снимка и календарь. Макроцикл, sentiment и события вводятся вручную с источником/временем; автоматической новостной ленты нет.
6. Перед бумажным входом обновите balance/equity, day-start, high-water и open risk в чекере. `ALLOW_PAPER` — локальная проверка, не live-разрешение.
7. Записывайте закрытые сделки и соблюдение плана. Журнал не синхронизирован с брокером и не меняет автоматически баланс чекера.

Практический порядок: [PLAYBOOK.md](docs/PLAYBOOK.md). Правила и экономика: [RULES.md](docs/RULES.md). Сетапы/контекст: [SETUPS.md](docs/SETUPS.md). Формат данных: [DATA.md](docs/DATA.md). API: [ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Автоматический выбор рынка и фирмы

В «Автопоиск» запустите фоновое исследование: программа сама сравнит рынки на train, зафиксирует первичного победителя и до трёх диагностических кандидатов до открытия holdout. Отказ победителя оставляет выбор пустым; удачная диагностическая строка не подменяет его.

Yahoo-список по умолчанию: EURUSD, XAUUSD, NAS100, BTCUSD, MES=F, MNQ=F, AAPL, MSFT. Доступны 1h/3mo или 1d/2y. При недоступной сети есть офлайн-скан четырёх архивов AAPL/MSFT/JPM/XOM за общий период 2015–2018.

Для каждого рынка применяются видимые **предположения исполнения**: расходы, multiplier, quantity step и плечо. Они не подтверждены как тариф брокера. Целый micro-futures контракт может не поместиться в риск-бюджет — ноль сделок допустим. Для единой модели расходов снимите выбор индивидуальных расходов; зафиксируйте решение до запуска.

Профиль фирмы выбирается по положительному моделируемому EV первой выплаты только для прошедшего первичного рынка и минимум 30 OOS-сделок. Нужны пользовательская проверка правил не старше 90 дней, HTTPS-источник и совместимая валюта. Учебные профили не дают рекомендации реальной фирмы. При неподтверждённых правилах или слабых данных результат — «подходящего кандидата нет».

Текущие сайты фирм заблокированы прокси, поэтому конкретная лучшая фирма автоматически не утверждается. После завершения результат можно перенести в лабораторию и условные сетапы; ордер не создаётся. Подробнее: [SCANNER.md](docs/SCANNER.md), [FIRM_SELECTION.md](docs/FIRM_SELECTION.md).

## Стратегии и проверки

Семь семейств: EMA pullback, Donchian breakout, RSI reversion, Bollinger reversion, trend momentum, inside-bar breakout и volatility expansion. Buy & Hold — ориентир. Это конечный набор гипотез, не «все стратегии на всех активах».

Сигнал вычисляется по закрытой свече, вход — следующий open. ATR-stop и target фиксируются на сигнале. Учтены плечо, quantity step, комиссия, spread, slippage и комиссия на quantity unit. При конфликте stop/target приоритет у стопа; неблагоприятный gap исполняется по open.

Параметры и главный кандидат выбираются на train; walk-forward окна предшествуют финальному holdout. Последняя выборка проверяет исходный выбор. Описательный bootstrap-интервал не исправляет всю неопределённость множественного поиска.

Для профиля правил используется полная непрерывная holdout equity-кривая с adverse OHLC marks. Replay проверяет поддерживаемые loss floors; target/days/consistency выводятся отдельно. Это не многослойное прохождение challenge/funded. Модель первой выплаты отдельно пересэмплирует OOS returns, включает fee попытки, split, consistency, отдельные стадии и наблюдаемую частоту сделок. Её вероятности условны на допущениях, не являются подтверждёнными прогнозами.

## Исследования на реальных архивах

В комплекте доступны четыре дневных архива **AAPL, MSFT, JPM, XOM** и полные отчёты. История заканчивается **7 февраля 2018 года**: это реальные архивные наблюдения, а не сегодняшние сигналы.

Первый эксперимент содержит 28 активных проверок; 23 дали положительный holdout после заданных расходов, **ни одна не прошла все внутренние фильтры**. Train-победители и все отказы сохранены: [RESEARCH_RESULTS.md](docs/RESEARCH_RESULTS.md).

Более широкий поиск проверил обучение на 485 активах того же архива. Shortlist из пяти кандидатов фиксировался на диске до открытия новых holdout; просмотренные четыре тикера исключены, отказ не заменялся другим результатом. **Все пять кандидатов отклонены**: holdout содержит только 11–15 сделок, меньше обязательных 20. Положительная альтернативная строка не переизбирается победителем. Протокол, все исходы и ограничения: [EDGE_SEARCH.md](docs/EDGE_SEARCH.md).

Источник — фиксированный публичный исторический snapshot с SHA-256. Survivorship bias, corporate actions, фактическое исполнение, календарь проп-фирмы и сегодняшние условия полностью не установлены. Положительная строка отчёта не становится подтверждённой выплатной стратегией.

Есть отдельные независимые проверки [GOOG, 2004–2013](docs/INDEPENDENT_RESULTS.md) и [ETH/BTC, 2018](docs/CRYPTO_RESULTS.md). Их периоды и валюты различаются; они не объединяются с USD-архивами в рейтинг текущих рынков. Квалифицированной стратегии эти эксперименты также не установили. Архивы объясняют работу проверки и не являются сегодняшними сетапами.

## Внешние цены и собственный CSV

Yahoo — необязательный публичный **неофициальный** исторический feed. Интерфейс позволяет запрашивать его по нажатию; запрос не подключает брокера и не торгует. В текущей облачной среде реальный запрос блокировался proxy **403**: обработка fixtures проверена, успешное получение текущей Yahoo-истории здесь не подтверждено.

Короткие названия требуют внимания: EURUSD → `EURUSD=X`, BTCUSD → `BTC-USD`, **XAUUSD → futures proxy `GC=F`**, **NAS100 → неторгуемый индекс `^NDX`**. Futures/index feed отличается от spot/CFD проп-счёта. При отказе используйте CSV; синтетические данные не подставляются как реальные. Подробнее: [FEEDS.md](docs/FEEDS.md).

CSV: `time,open,high,low,close,volume`. `time` — UTC open-label (`Z` или `+00:00`), каждый бар уже полностью закрыт. Порядок строго возрастающий без дублей; положительные конечные OHLC с корректной оболочкой. До 30 000 баров; HTTP body до 5 MiB, CLI CSV до 12 MiB; исследованию нужно минимум 300 баров.

Quantity — выбранные units/contracts, не автоматические lots. `contract_multiplier` — деньги счёта за движение цены на 1,0 на единицу quantity. При другой валюте требуется отдельная конвертация. Комиссия и slippage — **bps за сторону**, spread — **полный**; `fee_per_unit` — денежная комиссия на единицу за сторону. Полные определения: [DATA.md](docs/DATA.md).

CLI:

```bash
python3 -m unittest discover -s tests -v
python3 -m propdesk demo --symbol EURUSD --output /tmp/prop-lab-demo.json
python3 -m propdesk validate-csv /path/to/candles.csv
python3 -m propdesk research --symbol YOUR_ASSET --csv /path/to/candles.csv --output /tmp/research.json
```

## Сохранение и обновления

SQLite: `.local/propdesk.sqlite3`, вне Git. Другой каталог задаётся `--data-dir` или `TRADING_DATA_DIR`. Резервную копию делайте при остановленном сервере; при копировании работающей базы нельзя игнорировать WAL. Экспорт CSV журнала не заменяет копию профилей и исследований.

«Обновления» проверяет `NeatherFrog/awesome-x402`, ветку `main`, и устанавливает совместимую опубликованную версию. Старое имя GitHub-репозитория сохранено. ZIP привязан к commit; updater проверяет структуру/манифест, делает backup, сохраняет пользовательское состояние и отказывается затирать изменённые исходники. Автоматический restart работает через лаунчер; при прямом запуске сервера нужен ручной перезапуск. Подробности: [UPDATES.md](docs/UPDATES.md).

## TradingView

Pine v6 экспортируется для семи семейств с **базовыми параметрами каталога**. Выбранные исследованием параметры переносите вручную. Проверьте компиляцию в Pine Editor, данные, commission/slippage, margin, multiplier и шаг quantity. Python-тесты не компилируют Pine; его execution engine отличается.

`POST /api/webhook/tradingview` принимает планировочный JSON с `symbol, side, price, strategy` и token в body либо Bearer header. Без `TRADING_WEBHOOK_TOKEN` маршрут выключен. Принятый сигнал сохраняется и не создаёт ордер. Нужен отдельный публичный HTTPS-вход; приватный локальный адрес TradingView недоступен. TLS-развёртывание не включено.

`.env.example` описывает имена; приложение не загружает `.env` автоматически. Не сохраняйте реальные токены в Git, exports или публичных настройках графика.

## Практические ограничения

Официальные текущие правила FTMO/Topstep через прокси не получены; их нужно сверить по продукту и договору. Автоматического получения правил нет. Доступность Yahoo и GitHub updater требует реальной сетевой проверки; сохранённая cloud-настройка не означает работающий запрос.

Нет live broker execution, платёжных операций, всех стратегий/активов, tick/order-book replay, полного funding/swap/borrow учёта и объединённого риска коррелированных позиций. Контекст сетапа вводится вручную и не доказывает финансовый эффект новостного фильтра.

Live-адаптер — отдельная задача: конкретная фирма, разрешение на автоматизацию, точные quotes/fills, сверка позиций, лимиты и аварийная остановка. Для текущего кабинета следующий содержательный этап — свежие проверенные данные и последовательный forward paper test.
